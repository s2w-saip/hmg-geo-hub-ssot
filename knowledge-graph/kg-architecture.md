# 지식그래프 아키텍처

LLM이 제안하고 사람이 확인한 것을 기준 판으로 발행한다. 분석은 그 판으로 엔티티를 브랜드에 잇는다.

`✓` = 시험 구현(PoC)으로 돌려 본 것이다. 운영 구현이 아니다. 표시 없는 것은 목표 설계다.

## 1. 목표 아키텍처 — 6계층

| 계층 | 구성 요소 |
|---|---|
| 데이터 소스 | LLM 응답(수집 답변 원문) ✓, 자동차 웹 소스(중고차 사이트 · 공공 자료) ✓ |
| 수집 | 소스 큐레이션(신뢰도 · 적합성), 크롤러 · 파서(공용 · 전용), 원천 스냅샷(원문 · 위치 · 시각) ✓ |
| 추출 | LLM 추출(엔티티 · 관계) ✓, 사전 대조(표기를 정규화해 엔티티 사전의 별칭과 맞춤) ✓ |
| 검증 | 자동 판정(이미 정한 판정 재사용) ✓, 사람 검수(HITL, 새 것만 한 번) ✓, 골드셋(사람 판정 모음) ✓ |
| 지식 | 지식그래프(온톨로지 v0.2) ✓, 기준 판(버전 발행 · 이전 판 보존) ✓, KG DB(판째 쌓음) ✓ |
| 활용 | 분석 모듈(엔티티 → 브랜드 매핑), 파이프라인(회차 버전 정보), 현황판 · 보기 화면(진행 현황 · 판 조회) ✓ |
| 거버넌스(모든 계층) | 감사 이력, 버전 관리 ✓, 근거 추적, 접근 제어 ✓ |

분석 모듈 · 파이프라인은 다른 파트다. KG DB는 파이프라인 그림의 KB DB다.

## 2. 처리 흐름과 역할

| 단계 | 역할 | 처리 → 데이터 |
|---|---|---|
| ① 소스 선정 | 소스 큐레이터: 신뢰도 · 적합성 평가 | 소스 레지스트리(대상 사이트 목록) |
| ② 수집 · 파싱 | 자동 | 수집기 · 파서 → 원천 스냅샷 ✓ |
| ③ 추출 · 정규화 | 자동 | LLM 추출 + 사전 대조 ✓. LLM 응답도 여기로 들어온다 |
| ④ 자동 판정 | 자동 | 사람이 이미 정한 것과 같으면 자동으로 판정한다 ✓ |
| ⑤ 사람 검수 | 도메인 검수자: 의미 확인 · 교정 · 승인 | 검수 화면 ✓. 새 것만 한 번 |
| ⑥ 발행 | 릴리스 매니저: 승인분 취합 · 발행 | 기준 판 vN ✓ → KG DB ✓. 발행한 판은 다음 추출의 엔티티 사전에 더한다 ✓ |
| ⑦ 활용 | 다른 파트: 분석 · 파이프라인 | 분석 모듈이 판으로 엔티티를 브랜드에 잇는다 → 추출 결과(Silver) |

- **자동 판정**: 사람이 이미 정한 것과 같으면 자동으로 판정하고, 자동 판정 표시를 남긴다.
- **새 것만 한 번**: 판에 없는 엔티티 · 별칭 · 관계만 사람이 본다. 그 판정은 그것이 나온 문서마다 자동 반영한다.
- **판이 사전으로**: 발행한 판이 다음 추출의 엔티티 사전에 더해져, 같은 표기를 처음부터 알아본다.

역할은 기능 단위다. 사람 수나 담당 배정이 아니다.

## 3. 받는 것 · 주는 것

### 받는 것

| 무엇 | 어디서 | 지금 |
|---|---|---|
| LLM 응답 원문 | 수집(응답 원문, Bronze) | 기존 시스템(앤써) DB 사본에서 고른 표본만 읽는다 |
| 자동차 웹 소스 | 중고차 사이트 · 공공 자료 | 국내 사이트의 브랜드 · 차종 목록을 시험 처리했다 |

### 주는 것 — KG DB, 판마다 한 벌

| 무엇 | 쓰는 곳 | 비고 |
|---|---|---|
| 판 ID · 지금 판 | 파이프라인 회차 버전 정보(엔티티 카탈로그), 분석 추출 규칙 버전 | 판은 지우지 않는다. 지금 판은 포인터 한 줄이 가리킨다 |
| 엔티티: 브랜드 · 차종 · 기업 · 국가, 자사 · 경쟁 표시 | 분석 엔티티 → 브랜드 매핑 | 사람이 확인한 것과 초안을 가른다 |
| 이름 · 별칭: 언어 · 종류 · 대조 조건 | 분석 엔티티 찾기 | 사람이 확인한 것과 초안을 가른다 |
| 관계: 차종 → 브랜드, 브랜드 → 소유 기업 · 출신 국가, 기업 → 모회사 · 본사 국가 | 분석 엔티티 → 브랜드 매핑 | 소유 · 모회사 · 본사는 시작 · 끝이 있다 |
| 엔티티 아님: 늘 아님 · 애매한 이름 | 분석 애매한 이름 | 애매한 이름은 문맥으로 판단한다 |

KG DB는 읽기 계정으로 읽는다. 접속 정보는 따로 전달한다. 테이블 · 필드는 지식그래프 저장소의 `poc/db/data-dictionary.md`에 있다.

## 4. 다른 파트와 정할 것

1. **연결 방식 · 새 판 알림**: KG DB를 바로 읽을지, 판 파일을 받을지. 새 판을 어떻게 알릴지.
2. **버전 표기**: KG의 버전은 판 ID다. 분석의 추출 규칙 버전 표는 KG를 git으로 적었다.
3. **기준정보의 원본**: 자사 브랜드 · 브랜드 엔티티 역할 · 인용 출처 분류를 서비스 DB와 KG 중 어디에 둘지. 서비스 입력 계약은 서비스 DB, 파이프라인 그림은 KB로 적었다. KG 판에는 자사 · 경쟁 표시가 있고, 인용 출처 분류 규칙은 없다.
4. **응답 원문을 읽는 곳**: 응답 원문(Bronze)과 분석 입력 준비 중 어디서 읽을지.

## 5. 용어

| 용어 | 뜻 |
|---|---|
| 지식그래프(KG) | 자동차 엔티티(브랜드 · 차종 · 기업 · 국가)와 그 이름 · 별칭 · 관계. 이 파트의 이름이기도 하다 |
| 기준 판(판) | 사람이 확인한 엔티티 · 별칭 · 관계(지식베이스)를 버전으로 낸 한 벌. 판 ID 예: `kb-0.5-20261104T070459Z` |
| 엔티티 사전 | 추출이 대조하는 이름 · 별칭 목록. LLM이 만든 초안을 포함하고, 발행한 판으로 갱신한다 |
| 사전 대조 | 표기를 정규화해 엔티티 사전의 별칭과 맞추는 단계. 글자 비교다 |
| 초안 | 기계가 쓰고 사람이 아직 확인하지 않은 엔티티 · 별칭 · 관계 |
| 자동 판정 | 사람이 이미 정한 것과 같은 후보를 자동으로 판정한다. 자동 판정 표시를 남긴다 |
| 사람 검수(HITL) | 도메인 검수자가 검수 화면에서 새 엔티티 · 별칭 · 관계만 확인 · 교정 · 승인한다 |
| 골드셋 | 사람 판정 모음. 추출 정확도를 재는 데 쓴다 |
| KG DB | 판을 쌓는 PostgreSQL. 지식그래프 저장소에서는 결과 DB, 파이프라인 그림에서는 KB DB라 부른다 |
