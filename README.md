# hmg-geo-hub-ssot

3파트 5인이 함께 보는 프로젝트 전체의 SSOT(Single Source of Truth).

## 대전제

**SSOT로 관리하는 모든 문서는 내용을 명확하게 전달할 수 있는 수준에서 가장 짧고 간결하게 정리된 문서로 가공해 넣는다.**

## 파트와 담당

| 파트 | 하는 일 | 담당 |
|---|---|---|
| 서비스 | 지표 정의와 계산(BFF), 화면, 지표 API, 프롬프트·기준정보 API | 김태호 |
| 분석 | 응답에서 정보 추출(AI 모델) | 신민철, 박보규 |
| 데이터 파이프라인 | 분석 입력 준비, Silver OBT 적재와 운영 반영 | 이시형, 김혜민 |

수집(AI 엔진 질의, 응답 원문)은 앤써가 맡는다.

## 폴더

| 폴더 | 내용 | 담당 |
|---|---|---|
| [shared/](shared/README.md) | 모든 파트가 참조: 전체 구조, 팀 간 데이터 계약, 용어, 운영 원칙 | 전원 |
| [service/](service/README.md) | 서비스(BFF): 지표 정의, 사전 집계, 캐시, 화면, 지표 API, 프롬프트·기준정보 API | 김태호 |
| [analysis/](analysis/README.md) | 분석 모듈: 추출 항목 정의, 추출 규칙 버전, AI 모델 | 신민철, 박보규 |
| [pipeline/](pipeline/README.md) | 데이터 파이프라인: 입력 준비, 스냅샷 적재·검증·운영 반영, 롤백 | 이시형, 김혜민 |

## 문서를 둘 곳

- 다른 파트가 읽어야 일할 수 있는 내용은 `shared/`에 둔다.
- 한 파트만 읽는 내용은 그 파트 폴더에 둔다.

## 처음 읽을 문서

- [shared/metric-processing-options.md](shared/metric-processing-options.md): 지표 가공 구조. 단계와 담당, 데이터 흐름, 팀 간 데이터 계약, 운영 반영, 운영 원칙.
- [shared/urls.md](shared/urls.md): 저장소, 서비스 주소, 프롬프트·기준정보 API, 레거시 프로젝트.

## 파일 형식

같은 내용을 두 형식으로 둘 수 있다. 파일 이름은 같고 확장자만 다르다.

- `.md`: AI가 읽기 쉬운 형식
- `.html`: 사람이 브라우저에서 보는 형식 (그림 포함)

**두 형식은 항상 함께 고친다.** 어느 쪽을 먼저 고치든 같은 변경을 다른 쪽에도 반영한다. 한쪽만 고친 상태로 두지 않는다.
