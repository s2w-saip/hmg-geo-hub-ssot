# 캐시 DB

필터 조회 결과를 다음 회차가 운영 반영될 때까지 저장해 두는 서비스 전용 DB다. 정본이 아니므로 지워져도 OBT 운영 스냅샷에서 다시 만든다. 전체 구조는 [shared/project-architecture.md](../shared/project-architecture.md).

## 담는 것

| 담는다 | 담지 않는다 |
|---|---|
| 필터 조회 결과. 조회 조건마다 1건 | 사전 집계(Gold: 필터 없는 초기 화면 값), 추출 결과(Silver), 프롬프트·기준정보 원본 |

## 저장 위치

- 서비스 PostgreSQL 안에서 Gold와 분리한 스키마 또는 DB에 둔다(예: `cache`).
- UNLOGGED 테이블로 만든다. 장애로 비워져도 된다.
- 백업하지 않는다.

## 캐시 키

`조회 조건(필터 포함) + 운영 스냅샷 ID + 지표 정의 버전`

- 같은 조건이 같은 키가 되도록 조건의 순서와 표기를 통일한 뒤 해시한다.
- 스냅샷 ID나 지표 정의 버전이 바뀌면 이전 결과는 저절로 쓰이지 않는다. 만료 시간(TTL)은 두지 않는다.

| 컬럼 | 내용 |
|---|---|
| `cache_key` | 위 키의 해시. 기본 키 |
| `snapshot_id` | 운영 스냅샷 ID |
| `definition_version` | 지표 정의 버전 |
| `query` | 조회 조건 원문 |
| `result` | 집계 결과 |
| `created_at` | 저장 시각 |

## 동작

1. BFF가 조회 조건, 현재 운영 스냅샷 ID, 지표 정의 버전으로 키를 만든다.
2. 캐시에 있으면 그 결과를 돌려준다.
3. 없으면 OBT 운영 스냅샷에서 전체를 세어 돌려주고 캐시에 저장한다. 표본이나 근사값을 쓰지 않는다. 기간 제한이 없어 첫 조회는 오래 걸릴 수 있다.
4. 새 스냅샷이 운영 반영되면(매니페스트로 확인) 이전 스냅샷 ID의 행을 지운다.

## 하지 않는다

- 필터 없는 초기 화면 값을 조회 시점에 대신 계산하지 않는다. 사전 집계가 늦거나 실패하면 보여 주지 않는다.
- 캐시 DB를 다른 파트에 열지 않는다.
